# 预估需求表 → 领星发货计划导入（FBA仓）

## 用途与边界

运营每周五发一次货，提前两周就把「下下周五」要发的量定在预估需求表里。本技能把那一列变成一个能直接上传领星的 xlsx。

| 输入 | 输出 |
|---|---|
| ① 预估需求表 xlsx（多 sheet，只用「库存表」） | ① 领星「导入发货计划产品（FBA仓）」19 列模板 xlsx |
| ② 发货日（默认自动算下下周五） | ② 抽查表（每款发货量 / 在售 / 在途 / 30天日均 / 是否新品） |

不做的事：不改发货量、不替用户填运输方式/物流商/发货仓库/计划发货时间（模板里这些列本来就留空，导入后在领星页面选）、不在领星里直接建货件（导入由用户自己在后台操作）。

## 三条铁律

### 1. 只读「库存表」这一张

用户明确过：其他 sheet 一律无视。**不要**去「订单表」「数据源」「库存明细」里捞 MSKU 或数量——那是别的口径（订单表是采购下单用，字段还不一样）。

### 2. 数量取「需求数量（发货日）」那一列，不取最后一列

库存表右侧有一串按周排的「需求数量（M.D）」列，每列 = 某一周要发的货。**列名里的日期就是要发货的那天。**

发货日算法：**今天之后（含当天）的第一个周五 + 14 天**。

举例：今天 2026-11-20 是周五 → 本周五 11/20、下周五 11/27、**下下周五 12/4**，就取「需求数量（12.4）」
（实际是 AC 列，10 款 / 7330 件）。

取错列的后果很直接：表里 11.20 那列是 11 款 / 3896 件，12.4 那列是 10 款 / 7330 件，两个数差一倍。

### 3. 只写这 6 列，其余空白一律不填

模板 19 列里，本技能只写 6 列：`*店铺` / `*包装类型` / `MSKU` / `*计划发货量` / `计划发货时间` / `备注`。

`FNSKU`、`SKU`、`单箱数量`、`箱数`、`运输方式`、`物流商`、`物流渠道`、`工厂直发`、`发货仓库`…全部留空——
**空白的不用填**，填了反而会和领星里的货件设置打架。

**`计划发货时间` 必须填**，就是算出来的发货日（本期 2026-12-04），**格式固定 `yyyy-mm-dd`**。
默认写成文本 `2026-12-04`（领星按这个字符串原样读，最不容易被认成空值）；要真日期值就加 `--date-style date`，
显示同样是 `2026-12-04`。这一列漏了或格式不对，导入时货件的计划发货日就为空，后面排车、算时效都跟着错。

## 新品首发怎么判（讲清依据，别凭感觉标）

**判定条件（5 个同时满足）：**

| 条件 | 列 | 含义 |
|---|---|---|
| 在售库存 = 0 | I | FBA 仓里没货 |
| 在途数量 = 0 | J | 没有在路上的 |
| 入库中 = 0 | K | 没有正在接收的 |
| 计划入库 = 0 | L | 也没排过入库计划 |
| 近30天日均销量 = 0 | G | 没卖出去过 |

**为什么是这 5 条**：这 5 项一起为 0，说明这个 SKU 在亚马逊上「没货、没在途、没卖过」——那就是还没上架，第一次发货自然是首发。
只要有一项不为 0，说明它已经在卖了，哪怕只卖了 1 件，也不算首发。

**真实例子（用 11.20 那列回归验证过）**：

| MSKU | 在售 | 在途 | 30天日均 | 判定 |
|---|---|---|---|---|
| JS-WP647A-1-V1（酒架） | 0 | 0 | 0.00 | ✅ 新品首发 |
| JS-WP650A-5-V1（海绵架透明） | 0 | 0 | 0.00 | ✅ 新品首发 |
| JS-WP650A-1-V1（海绵架黑色） | 0 | 0 | 0.00 | ✅ 新品首发 |
| JS-WP650A-2-V1（海绵架透明） | 0 | 0 | 0.00 | ✅ 新品首发 |
| JS-WP103B-4-L1（多边形角落架三件套银色） | 43 | 96 | 2.33 | ❌ 不标（已在售） |
| BS-13（四钩肥皂架本色） | 9019 | 7200 | 203.50 | ❌ 不标 |

这 6 行跑出来和用户上一版手工做的 `导入发货计划产品（FBA仓）-0507 (21).xlsx` 一字不差——哪天改了判定规则，先拿 11.20 这列回归一次，对不上就是改错了。

**取不到数怎么办**：如果「近30天日均销量」是公式且没缓存结果（读出来是空），脚本**不会**把它当 0，而是不标新品，并在结尾列出这些 MSKU 让用户人工确认。宁可漏标，不可错标——错标成新品首发，领星那边货件类型会走错。

## 操作步骤

```bash
# 最常用：周五跑，自动算下下周五
python scripts/build_shipment_import.py \
  --src "D:/Users/Administrator/Desktop/巨杉店铺/巨杉美国预估需求表2026.11.20.xlsx"

# 手工指定几款几件、指定发货日（用户直接报「某款发多少」时用）
python scripts/build_shipment_import.py \
  --src "..." --ship-date 2026-11-27 \
  --items "WP650A-5-V1=350,WP650A-1-V1=200,WP650A-2-V1=200"

# 只想看看发什么，不写文件
python scripts/build_shipment_import.py --src "..." --dry-run

# 指定发货日（补做上周的、或改期）
python scripts/build_shipment_import.py --src "..." --ship-date 2026-12-04
```

### 用户只报几个款号时，走 `--items`

运营常直接甩一句「WP650A-5-V1 / WP650A-1-V1 / WP650A-2-V1，350 / 200 / 200，下周五发」。
这时不要去找需求数量列（那一周可能根本没填），用 `--items` 把款号和数量手工喂进去。

**关键：用户报的是「产品编号」，领星模板 C 列要的是「MSKU」，两者不一样。**

| 用户说的 | 库存表 B 列 产品编号 | 库存表 D 列 MSKU | 模板 C 列写 |
|---|---|---|---|
| WP650A-5-V1 | WP650A-5-V1 | **JS-WP650A-5-V1** | JS-WP650A-5-V1 |
| WP650A-1-V1 | WP650A-1-V1 | **JS-WP650A-1-V1** | JS-WP650A-1-V1 |
| WP103 | WP103 | **BS-113** | BS-113 |

`--items` 两个都认（大小写不敏感），输出统一换成 MSKU；找不到就报错，不会静默跳过。
型号名（如 `JS-new-535B-1`）照抄别改大小写。

`--items` 模式下新品首发仍按 5 条件自动判；确实要全部标新品就加 `--all-new`。

默认输出到源文件同目录，文件名 `导入发货计划产品（FBA仓）-0507_1204发货.xlsx`（后缀 = 发货日 MMDD）。

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--src` | 必填 | 预估需求表 xlsx |
| `--sheet` | `库存表` | 只读这张 |
| `--outdir` | 源文件目录 | 输出目录 |
| `--out` | — | 直接指定输出全路径，优先于 `--outdir` |
| `--ship-date` | 自动算 | 发货日 `YYYY-MM-DD` |
| `--weekday` | `4` | 每周几发货，0=周一…4=周五 |
| `--lead-weeks` | `2` | 提前几周，2 = 下下周 |
| `--store` | `巨杉-US` | 领星店铺名（巨杉美国/青阳美国 都是这家） |
| `--pack` | `原厂包装` | 包装类型，另一个可选值是「混装」 |
| `--tag` | `新品首发` | 新品备注文案 |
| `--items` | — | 手工指定款号与数量，跳过需求数量列。`"WP650A-5-V1=350,WP650A-1-V1=200"`，产品编号或 MSKU 都认 |
| `--all-new` | 关 | 强制所有行都标新品首发（默认按 5 条件自动判） |
| `--date-style` | `text` | 计划发货时间写法：`text`=文本 `2026-12-04`；`date`=真日期值（显示同为 yyyy-mm-dd） |
| `--allow-nearest` | 关 | 找不到发货日那列时，允许退而用最接近的一列 |
| `--dry-run` | — | 只打印抽查表 |

## 交付方式

脚本会先打印一张抽查表，再写文件，最后回读校验行数、合计、计划发货时间：

```
发货日 2026-12-04（周五）· 取列「需求数量（12.4）」· 第 1 行表头 · 10 款 / 合计 7330 件

 # | MSKU           | 品名                |  发货量 |  在售 |  在途 | 30天日均 | 备注
 1 | BS-13          | 四钩肥皂架本色        |   4080 |  9019 |  7200 |   203.50 |
 ...
10 | JS-WP630A-2-V1 | 洗衣机侧边收纳白色     |    258 |    94 |   330 |     6.33 |
合计 10 款 / 7330 件；其中新品首发 0 款 / 0 件

已生成：D:/.../导入发货计划产品（FBA仓）-0507_1204发货.xlsx
回读校验：10 行 / 7330 件 / 计划发货时间 2026-12-04 缺失或错填 0 行 / 备注 0 行 → 通过
```

**把抽查表和文件路径一起给用户**，让他扫一眼数量、发货日、备注对不对，再自己去领星上传导入。
不要替他点领星后台（浏览器操作一律由用户执行）。

## 已知坑

1. **表头不一定在第 1 行**。库存表目前是第 1 行，但订单表是第 4 行。脚本在前 20 行里认「产品编号 + MSKU」同时出现的那行，找不到就报错，不会瞎猜。
2. **库存表里的 `#DIV/0!` / `#REF!`** 是公式报错，脚本按「取不到」处理，不当 0，避免误判新品。
3. **需求数量列名只有月.日，没有年**。脚本按发货日的年份补，遇到「12 月表里出现 1 月列」会自动算次年。
4. **表里没有目标日期那一列时，脚本直接拒绝生成**。这种情况基本等于「这一周的排货还没填」，
   用上一列出文件会导致同一批货发两遍。脚本会告诉你实际取到的是哪一列，让人去补列；
   确实要用最接近那列才加 `--allow-nearest`。**不要为了「先把文件跑出来」而随手加上这个参数。**
5. **同一款不要出现两次**。库存表偶尔会有重复 MSKU 行（不同变体写法），跑完看抽查表款数是否和你数的一致。
6. **`计划发货时间` 的格式是 `yyyy-mm-dd`（横杠，不是斜杠）**。领星这一列不认 `2026/12/4`。
   脚本默认写文本 `2026-12-04`，单元格格式设为「文本」，Excel 里看到的就是这 10 个字符，不会被二次格式化；
   回读校验会逐行核对，任何一行不是这一天就报「不一致」。
7. **同一批货别出两次**。用户说「下周五发」而表里原本某列也有同款同量时，先确认那批是没发成要改期，
   还是新追加。两列都导进领星就是重复计划。交付时把「和哪一列数量重合」点出来让他自己判断。
