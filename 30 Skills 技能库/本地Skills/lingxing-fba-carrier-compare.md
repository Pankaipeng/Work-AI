# 货代整批比价（两家 → 选一家）

## 用途与边界

**默认不启用。** 用户没提"比价/哪家便宜/选哪家"时不要主动调用——直接走 `lingxing-fba-shipping-plan` 出计划。

本技能只做一件事：**同一批货，两家货代各报一个整批价，差多少，建议走哪家。**

核心口径（运营已确认，不要自行改动）：

1. **整批只走一家货代，绝不逐票混搭。** 所以比价单位是「整批合计运费」，不是"每票各挑最低"。
2. 逐票的差异只用来解释"差在哪几票"，用一列 `该票较低（参考）` 呈现，**不作为选谁的依据**。
3. 只比**含税海卡**（元/KG）；不含税（元/CBM）、整柜直送、SEND、海派不参与。
4. 每家在每个仓库取自己**最便宜**的渠道，再把整批加总。
5. 某家缺某个仓库的报价 → 这家**不能整批承运**，直接排除并说明缺口，不能拿其它仓的价补。

输出了什么：`货代比价_2026-11-04.xlsx`（比价结论 / 逐票明细 / 校验报告）+ 同名 `.json`，控制台再打一遍结论。文件名按当天日期生成，同日重复执行加 `_2`。

## 开始前先收集输入

1. **装箱单**（必需，可多份）——与发货计划技能同一份文件。
2. **货件列表**（必需）——亚马逊后台「货件」导出，提供仓库代码。
3. **两家货代的本周报价表**（必需，2 份）——文件名含「恒信/辛巴」「凯琦」等；**每周更新，不要用上周的**。

只要这三样。地址库/型号库/发票口径都不需要——本技能不出计划。

## 执行流程

### 1. 跑比价脚本

```bash
export PYTHONUTF8=1

python scripts/compare.py \
  --packing "装箱单1.xlsx" "装箱单2.xlsx" \
  --shipments "货件列表.xlsx" \
  --quote "恒信（辛巴）海运报价-2026-11-02.xlsx" "凯琦美线-青吉VIP价2026.11.2.xlsx" \
  --out "./比价结果"
```

`--quote` 顺序即结论里的展示顺序（先传的在前）。表头认不出时用 `--packing-sheet/--shipment-sheet`。

### 2. 读结论（这是本技能的主要交付）

看同名 `.json` 的 `结论`：

- `建议货代`：整批合计运费最低、且能覆盖全部票的那一家。
- `结论`：一句话，含两家合计金额与差额。
- `说明`：时效权衡（最慢天数差）、差额 <2% 的提醒、哪家有缺口。
- `可整批`：每家是否覆盖全部票。

**必须把这句话原样交给用户**，不要只丢一个表格让用户自己算。

### 3. 判断要不要提醒

- **差额 <2%**：明确说"差得很少，建议结合时效/账期/服务定"，不要硬推便宜那家。
- **便宜那家更慢**（最慢天数差 >3 天）：必须点出"省 X 元但要慢 Y 天"，让用户决定。
- **有缺口**：说清哪几票、哪个仓，别让用户以为这家能走。
- **只有一家能走**：如实说"另一家缺 N 票，本来就不能整批走"，这时候比价没有意义。

### 4. 汇报

给一张两家对比表（覆盖票数 / 计费重 / 合计运费 / 均单价 / 时效范围 / 是否可整批），再给结论一句话 + 风险提醒，最后 `present_files` 打开 xlsx。

### 5. 交回发货计划

用户定了货代后，**不要在本技能里继续出计划**，转 `lingxing-fba-shipping-plan`，只传选定那家的报价表。

## 关键口径（易错）

- **不要逐票混搭**：即使 A 在 4 票更便宜、B 在 1 票更便宜，结论也只能是"整批走 A，合计差 ¥X"。混搭会破坏货代对账与提货安排。
- **合计 = 逐票运费相加**，不是「均单价 × 总重」。
- **计费重 = MAX(实重, 体积重÷6000)**，0.5KG **向上**进位（197.1 → 197.5）。两家计费重通常相同，差的是单价。
- **报价表的起收重量（51KG+/101KG+）不逐票套用**——公司整批周装量累计能满足起收，货代按实际计费重结算；所以 7.4 元/KG（起收 101KG）对 65KG 的小票仍然可用。开关：config `quote.use_min_weight`（默认 `false`）。
- **只取含税列**；起运地只取华南（深圳/广州/中山/汕头），凯琦一格里有多套起运地价，取第一套。
- **缺口不等于 0 元**：某家缺票时它的合计只是一部分，绝不能拿去和另一家的全量合计比大小。
- 差额占比 = 差额 ÷ 较低那家的合计，不是 ÷ 较高那家。

细节见 `references/compare-rules.md`（取价口径、结论话术、验证基线）。

> **运营向说明**：本技能与 `lingxing-fba-shipping-plan` 属于同一套流程（比价 → 出计划 → 发唛头），
> 面向运营的简明说明在两个技能的共用文档里：`~/.workbuddy/skills/lingxing-fba-shipping-plan/使用说明.md`。

## 脚本约定

- 只依赖 `openpyxl`；`readers.py / quoting.py / quote_parser.py` 与发货计划技能**同源**，报价表结构适配逻辑一致，改一处记得同步另一处。
- 入口只有 `scripts/compare.py`；结论生成在 `conclude()`，话术要改就改这里。
- 修改口径优先改 `config.json`（`quote.origins` / `max_transit_days` / `channel_blacklist`）。
