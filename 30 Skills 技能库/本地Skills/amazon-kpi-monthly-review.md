## 核心口径速查

| 项 | 口径 |
|---|---|
| 销售额 | 财务部口径，`实际 / 目标 × 60` |
| 抽查款销量 | 领星 `volume`（父 ASIN，`date_type=purchase`） |
| 广告费占比 | `spend / amount` |
| 销量达成率得分 | <80% → 0；80–90% → 1；≥90% → 4 |
| 广告占比完成率得分 | >140% → 0；100–140% → 0.5；≤100% → 1 |
| 每款满分 | 5 分（销量分 + 广告分） |
| 长仓费 | >0 不得分；有豁免审批按满分，金额保留、只改得分并备注 |

## 三个最值得记的坑

1. **抽查款标红是单元格内局部富文本**，`openpyxl` 读 `cell.font.color` 读不到，必须解压 `xl/sharedStrings.xml` 找 `<rPr>` 里的 `rgb="FFFF0000"`，否则会漏挑或挑错款。
2. **edsdk 的 `row/col` 是 0 起始**，按 Excel 行号写入会整体偏移一行一列；**公式会被写成双等号 `==`**，必须用 openpyxl 收尾修，同时补 `number_format`。
3. **规则每月可能变**（9 月只有两档、10 月拆成三档）。永远先读当月模板 F 列原文，再用上月已填得分反推验证一遍。

## 1. 输入清单（缺哪项就停下来问，一次问全）

| 输入 | 形式 | 用途 |
|---|---|---|
| 当月绩效表（模板） | `员工个人绩效考核表M月-运营岗-<姓名>.xlsx` | 结构、考核项、评分规则原文 |
| 上月绩效表 | 同上，M-1 月 | 反推口径、核对评分规则是否变化 |
| 抽查款表 | `各店铺运营计划复盘时间安排-M月-抽查款.xlsx` | 当月抽查哪几款（红色标记） |
| 财务部月度数据 | 截图或表格 | 销售额、广告费、广告费占比、长仓费 |
| 运营计划目标 | 利润推演表（或截图） | 计划销量、计划广告费占比 |
| 长仓费豁免审批 | 截图 | 有豁免才能按满分计 |
| 产品知识考试结果 | 用户口述 | 通过 5 分 / 未通过 0 分 |

## 2. 取数

### 2.1 抽查款识别（易错点）

抽查款在表里是**单元格内局部富文本**标红，`openpyxl` 读 `cell.font.color` 读不到，会漏判。

```bash
cd /tmp && rm -rf xk && mkdir xk && cd xk && unzip -o -q "<抽查款表.xlsx>"
python -c "
import re
s=open('xl/sharedStrings.xml',encoding='utf-8').read()
for m in re.finditer(r'<si>(.*?)</si>', s, re.S):
    t=m.group(1)
    if 'WP' in t: print(t[:600]); print('---')
"
```

在 `<rPr>` 里找 `rgb="FFFF0000"` 的那一段文字，就是标红的型号。

### 2.2 领星取数（父 ASIN 维度）

```
toolId: query_product_performance_asin_lists
params: {
  sids: "<店铺sid>",
  start_date / end_date,
  summary_field: "parent_asin",
  date_type: "purchase",           // 下单时间口径
  currency_code: "USD",
  turn_on_summary: 1,
  length: 500
}
```

关键字段：`volume`（销量）、`amount`（销售额）、`spend`（广告费）、`return_amount`（退款）、`principal_names`（负责人）、`parent_asin`。

- 广告费占比 = `spend / amount`，不要用别的口径。
- 按负责人汇总时，一行可能挂多个 `principal_names`，需要拆分累加。
- 拿到数据先做**一致性校验**：用上月的实测数去对一遍上月表里已填的数字，对得上才说明口径没错。

### 2.3 计划目标（利润推演表）

在运营计划表的「利润推演」sheet 里按月份块取两列：**销量合计**、**推广（%）**。

核对合计口径的方法：拿同模板的历史月份块看两个合计的比值是否与本月一致
（例：本月 1060 销量 / 2290 平均在库 ≈ 2.16，历史 1570 / 3460 ≈ 2.20，比值一致 → 确认 1060 是销量合计）。

计划表可能有新旧两版，**以用户最终确认的那版为准**，并把差异指出来。

### 2.4 财务口径

销售额优先用财务部口径（附表里注明来源与计算式），领星数据只做交叉校验，差额定性为「结算与退款确认时点不同」，不影响得分。

## 3. 计分规则

**规则每月可能变，一定先读当月模板 F 列原文，不要沿用上月。** 2026-10 版比 9 月更细：

| 维度 | 分段 | 得分 |
|---|---|---|
| 销量达成率 | < 80% | 0 |
| | 80%–90% | 1 |
| | ≥ 90% | 4 |
| 广告费占比完成率（实际 ÷ 计划） | > 140% | 0 |
| | 100%–140% | 0.5 |
| | ≤ 100% | 1 |

- 每款满分 5 分（= 销量分 + 广告分），抽查几款就几款。
- 销售额：`实际 / 目标 × 60`（权重 60%）。
- 长仓费：> 0 不得分；**有豁免审批则按满分**，金额本身保留在「实际」列，只改得分并写备注。
- 产品知识 / 领星下单发货 / 封样签字：通过即满分。

规则验证方法：用上月表的实际数字把规则重算一遍，结果与表里已填得分一致才继续。

## 4. 产出结构

与上月表保持同一套 sheet（用户要求「数据源和计算口径做在附表里」）：

| Sheet | 内容 |
|---|---|
| `月度` | 主表，按模板填实际完成情况 + 自评得分；合计公式确认覆盖全部行（`=SUM(J5:J10)`，别只加到中间某行） |
| `财务数据` | 上：结构化口径（实际/目标/达成率/得分 + 数据来源 + 计算式）；下：财务部原表截图 |
| `运营计划` | 逐款核算表（实际/计划/达成率/得分，用 `IF` 公式分段），下方贴计划原表截图 + 口径说明 |
| `长仓费减免` | 有豁免才建：审批要点（店铺/SKU/金额/原因/申请人/状态/处理方式）+ 审批单截图 |

## 5. 工具链与坑

写表两条路：`workbuddy-local-office-edit`（edsdk，能实时预览、能插图片）或 `openpyxl`（能精确控制格式）。实践上用 edsdk 写内容和图片，用 openpyxl 收尾修格式。

| 坑 | 现象 | 处理 |
|---|---|---|
| edsdk 行列是 **0 起始** | 按 Excel 行号写入会整体偏移一行一列 | `row/col` 都减 1；写错用 `sheet_clear_range_cells` 清 |
| 公式被写成双等号 | openpyxl 读出 `'==A1+B1'`，Excel 报错 | openpyxl 统一修：`c.value = '=' + c.value.lstrip('=')` |
| `sheet_set_cell_style` 的 `number_format` 不生效 | 百分比显示成小数 | 用 openpyxl 设 `number_format` |
| 文件被编辑器/预览占用 | `PermissionError`，`mv` 失败 | `close_file`（池里的 `file_id` 可能是编辑器 ID 而非路径）→ 再另存覆盖 |
| 图片锚点 | 插入后位置不对 | `sheet_insert_float_image` 的 `row_index/col_index` 同样是 0 起始 |

收尾必做（openpyxl 复检）：双等号残留数、各 sheet 图片数、合并单元格数、主表得分与合计公式。

## 6. 交付前自检

1. 抽查款型号与表里红色标记一致，款数一致
2. 每款得分能按规则手算复现
3. 合计 = 各项之和，且公式覆盖所有行
4. 附表里的实际值、计划值、得分三者能互相对上
5. 缺数据的项留空并在汇报里点名，不要填 0 或估算
6. 把「这个月比上月低/高的地方」单独讲出来，让用户知道风险点
